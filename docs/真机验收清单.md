# 真机验收清单

## relay-e2e-spike

探路 change：iPad 经阿里云 ECS 上的零知识 relay，端到端加密连回开发机的共享 daemon。对应 delta spec `relay-e2e-transport`。以下逐条真机验收，全部通过方可归档。

前置：ECS 已按 `relay-server/DEPLOY.md` 部署好 relay-server；开发机已起共享 daemon（有可用 control.sock）；iPad 已装带 RelayTransport + 配对导入 UI 的构建。

### 一、relay 服务端（ECS）

- [ ] 真 ECS 起 relay-server（systemd `active (running)`）。
- [ ] `curl http://<ecs-ip>:9000/health`（或 `wss` 前置后 `curl https://relay.example.com/health`）返回 `{"ok":true}`。
- [ ] 安全组 / 防火墙已放行对应端口（9000 或 443），iPad 与开发机均可达。

### 二、开发机拨出（relay-dialout）

- [ ] 开发机跑 `relay-dialout`（正确的 `RELAY_URL` + `CONTROL_SOCK`）拨出成功，终端打印 `relay-dialout 已拨出 ... (role=devMachine)`。
- [ ] 终端打印出配对载荷 `codexrelay://pair?relay=&sid=&pk=&pc=&exp=`（10 分钟内有效）。
- [ ] relay-dialout 桥接的是**开发机现有共享 daemon**（复用 `~/.codex/control.sock`），未自行 spawn 独立 app-server；退出时只停自己 spawn 的 proxy 子进程，desktop GUI 的 app-server 不受影响。

### 三、iPad 配对 + 端到端往返

- [ ] iPad 在配对导入界面粘贴 `codexrelay://pair?...` 载荷，解析成功（relay 地址 / sessionId / 开发机公钥 / pairingCode / 过期时间字段齐全）。
- [ ] iPad 经 RelayTransport 通过 relay 连上开发机（握手完成，建立 SecureSession）。
- [ ] 在 iPad 建一个会话并跑一个 turn：请求发出、响应回来，内容正确往返（无乱码 / 无截断 / 无丢帧）。

### 四、零知识（relay 不可见明文）

- [ ] 在 ECS relay 侧抓包 / 打印经过的帧，确认转发内容是密文（SecureEnvelope），无法还原出 JSON-RPC 明文；relay 只按 sessionId 撮合转发，不解密不解析。

### 五、真同步不被破坏

- [ ] iPad 经 relay 与 desktop 连到**同一个共享 daemon**：iPad 与 desktop 订阅同一 thread，一端产生的 turn / 增量能在另一端看到 live 广播（跨端真同步保持，未被 relay 通道破坏）。

### 六、传输并存（relay 与 SSH）

- [ ] relay 连接与既有 SSH 连接在 `MachineConfig` 中并存；在两种 transport 间切换，各自独立工作、互不干扰（切到 relay 不破坏 SSH 配置，反之亦然）。

### 七、双向认证 + 一次性口令

- [ ] 用**错误 / 无效**的 pairingCode（一次性口令）发起握手，被开发机侧明确拒绝（防冒充：开发机验 iPad 签名 + 校验 pairingCodeProof）。
- [ ] 同一 pairingCode **用过一次后失效**：首次握手成功后，再用同一口令二次握手被拒（`pairingAlreadyUsed`）。
- [ ] iPad 侧验证开发机身份（校验开发机签名 / 公钥），身份不符时拒绝连接。

### 八、错误可见（不静默挂死）

- [ ] 配对信息错误 / 格式非法 / 已过期（`exp` 超时）→ iPad 明确报错，不静默挂死。
- [ ] relay 不可达（ECS 宕 / 端口不通）→ iPad 明确报错，且可重试。

### 九、配对导入 UI 基线（项目级 UI 恒定原则）

- [ ] 配对导入界面在**横屏 / 竖屏**下布局均正常（两个朝向都测，不只测单一朝向）。
- [ ] 软键盘弹出 / 收起时界面无遮挡、无跳变；粘贴 / 输入交互正常。
- [ ] 外接键盘下可正常粘贴 / 编辑 / 提交配对载荷。

### 十、已知限制（记录，非阻塞）

- [ ] （可选）弱网 / 中途断线：当前无自动重传 / 断点续传，断线需手动重连。记录此已知限制，留后续 change 处理。

## relay-pairing-and-resilience 真机联机验收（待真机）

前置：开发机装最新 `relay-dialout`（信任列表 + 二维码 + 撤销 CLI）；iPad 装含相机扫码 + 受信任复连 + 断线重连的构建。真机才能测相机/真弱网。

### 一、扫码配对（相机 UI，模拟器不可测）
- [ ] 8.1 开发机首配模式启动，终端打印 ASCII 二维码（三定位角标可辨）+ `codexrelay://` 明文兜底；iPad「扫码」按钮唤起相机、扫开发机终端二维码 → 解析成功进入配对握手、建立 relay 机器
- [ ] 8.2 iPad 相机权限首次弹窗文案正确（NSCameraUsageDescription 中文）；拒绝权限后「扫码」提示不阻断、手动粘贴入口仍可用完成配对
- [ ] 8.3 扫到非法/过期二维码明确报错不挂死；扫码全屏 cover 横竖屏切换预览铺满不错乱（videoOrientation 目视）

### 二、免配对复连（信任持久化 + 稳定房间）
- [ ] 8.4 首次配对成功后，开发机 `~/.codex-relay-dialout/trusted-ipads.json` 出现该 iPad 记录（0600 权限）；重启开发机进复连模式（终端打印「等待受信任 iPad 复连」、不吐配对载荷），iPad **免扫码/免配对**自动连上、跑通 turn
- [ ] 8.5 一 iPad + 多开发机：iPad 对 A、B 两台开发机各自首配一次后，之后连任一台均免配对（各机器独立稳定房间/信任）
- [ ] 8.6 `relay-dialout --list-trusted` 列出受信任 iPad；`--forget <label>` / `--forget-all` 撤销后，该文件对应记录消失，且 CLI 命令**不吐**一次性配对载荷

### 三、断线自动重连 + resync
- [ ] 8.7 真弱网/切网/短时断网：iPad relay 连接断后自动指数退避重连、重新握手成功，经 `thread/resume` 补齐断线期 desktop 产生的内容，会话一致（不丢不重）
- [ ] 8.8 退避达上限（持续无网）后停止重连、toast「连接失败，请稍后重试」、保留机器；恢复网络后手动重连成功
- [ ] 8.9 失败区分：开发机未开机/房间无对端 → 提示「连接失败」（传输失败，不误报信任撤销）；未受信任 iPad 连到开发机正在服务的房间收到 RejectHello → 提示「已被移除信任，请重新配对」并引导回配对入口

### 四、能耗验证（用户要求项，具体方案后续敲定）
- [ ] 8.10 **能耗验证**（方案待定）：验证断线重连的退避+硬上限不无限空转、app 进后台暂停重连不持续烧电、主动断/trustRevoked 为终态不再重连。可选手段：Xcode Energy/Instruments（Energy Log / Network）观察后台断网时无周期性 radio 唤醒；对比旧 SSH 无界重连的耗电基线。具体验证方案（工具、时长、指标阈值）后续敲定，先登记占位

### 五、安全红线（真机复核）
- [ ] 8.11 E2E 密钥独立于 SSH（独立 Keychain account）；relay 服务端抓包只见密文信封（含 SecureReady 走加密通道，stableSessionId 不明文过 relay）；免配对/复连/重连全程 iPad 与开发机 Ed25519 双向验签未被跳过（改错开发机身份/篡改帧应拒连）

### 六、UI 基线（项目级恒定原则）
- [ ] 8.12 扫码/配对导入界面横竖屏 + 软键盘（不遮挡）+ 外接键盘（可编辑粘贴）均正常

## custom-resizable-columns（自绘可调宽三栏，已归档 2026-07-25，PR #37 合入 master 31c7a1f）

前置：装最新构建（模拟器已装 `com.tangyujie.codexremote`，真机同构建）；建议连一台真实 daemon 让中栏有重内容（对话）以测掉帧。

### 一、拖拽手感与约束

- [ ] 1.1 拖左分隔线：左栏随手指平滑变宽、**跟手不掉帧**；慢速拖动**无来回抖动**（D2 固定坐标系 + 起点锚差分）。

### 二、横竖屏一致

### 三、列宽持久化（D7）

- [ ] 3.2 调整列宽 → 杀进程冷启动（或系统回收后重开）：**列宽恢复到上次值**（读 UserDefaults）。

## reconnect-resync

change：iPad 经 relay 断线重连后会话正确恢复。对应 delta spec `ipad-reconnect-resync` + `ipad-approval-handling`。以下逐条真机验收（守 `ui-adaptation-baseline`：横竖屏各验一遍）。

前置：iPad 已装本 change 构建，经 relay 连回开发机共享 daemon；可人为断网（关 Wi-Fi / 断 relay）制造重连。

### 一、item 1 — 审批重放不重复卡

- [ ] 1.1 触发一个审批（如危险命令）→ 审批卡出现 → 人为断网 → 恢复网络重连：同一审批**仍只有一张卡**（无双卡），卡状态回到可操作（`awaitingRecovery` 已清）。
- [ ] 1.2 断线期间**不自动批准/不丢弃**：断网时未决审批卡保留，重连前不被自动放行。
- [ ] 1.3 横屏、竖屏各验一遍 1.1。

### 二、item 2 — 重连收敛（切换即刷新 + 审批全局兜底）

- [ ] 2.1 当前查看的 thread 断线期间产生新内容 → 重连后正文**收敛到最新**，无重复/丢失。
- [ ] 2.2 断线重连后切到一个后台 thread：经 resume 收敛见**最新**内容，不停留在断线前。
- [ ] 2.3 某后台 thread 断线期间有未决审批 → 重连后切过去：**审批已在**（全局通道兜底）且不重复。
- [ ] 2.4 横屏、竖屏各验一遍 2.1/2.2。

### 三、item 3 — 出站离线队列（断线攒、重连按序补发）

- [ ] 3.1 断网期间连发 3 条消息 → 3 条均**乐观回显**、无一丢失 → 恢复网络：**按发出顺序自动逐条发出**，无需手动重发。
- [ ] 3.2 补发**无重复气泡**（仍 3 条用户消息，不因补发再回显一遍）。
- [ ] 3.3 连接已 `.ready` 时正常直发（不入队）。
- [ ] 3.4 断线期间 interrupt/steer、审批回复**不入队**（不随补发被误发）。
- [ ] 3.5 横屏、竖屏各验一遍 3.1。
