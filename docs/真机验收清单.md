# 真机验收清单

## relay-e2e-spike

探路 change：iPad 经阿里云 ECS 上的零知识 relay，端到端加密连回开发机的共享 daemon。对应 delta spec `relay-e2e-transport`。以下逐条真机验收，全部通过方可归档。

前置：ECS 已按 `relay-server/DEPLOY.md` 部署好 relay-server；开发机已起共享 daemon（有可用 control.sock）；iPad 已装带 RelayTransport + 配对导入 UI 的构建。

### 一、relay 服务端（ECS）

- [ ] 真 ECS 起 relay-server（systemd `active (running)`）。
- [ ] `curl http://<ecs-ip>:9000/health`（或 `wss` 前置后 `curl https://relay.example.com/health`）返回 `{"ok":true}`。
- [ ] 安全组 / 防火墙已放行对应端口（9000 或 443），iPad 与开发机均可达。

### 二、开发机拨出（relay-dialout）

- [ ] 开发机跑 `relay-dialout`（正确的 `RELAY_URL` + `CONTROL_SOCK`）拨出成功，终端打印 `relay-dialout 已拨出 ... (role=devMachine)`。
- [ ] 终端打印出配对载荷 `codexrelay://pair?relay=&sid=&pk=&pc=&exp=`（10 分钟内有效）。
- [ ] relay-dialout 桥接的是**开发机现有共享 daemon**（复用 `~/.codex/control.sock`），未自行 spawn 独立 app-server；退出时只停自己 spawn 的 proxy 子进程，desktop GUI 的 app-server 不受影响。

### 三、iPad 配对 + 端到端往返

- [ ] iPad 在配对导入界面粘贴 `codexrelay://pair?...` 载荷，解析成功（relay 地址 / sessionId / 开发机公钥 / pairingCode / 过期时间字段齐全）。
- [ ] iPad 经 RelayTransport 通过 relay 连上开发机（握手完成，建立 SecureSession）。
- [ ] 在 iPad 建一个会话并跑一个 turn：请求发出、响应回来，内容正确往返（无乱码 / 无截断 / 无丢帧）。

### 四、零知识（relay 不可见明文）

- [ ] 在 ECS relay 侧抓包 / 打印经过的帧，确认转发内容是密文（SecureEnvelope），无法还原出 JSON-RPC 明文；relay 只按 sessionId 撮合转发，不解密不解析。

### 五、真同步不被破坏

- [ ] iPad 经 relay 与 desktop 连到**同一个共享 daemon**：iPad 与 desktop 订阅同一 thread，一端产生的 turn / 增量能在另一端看到 live 广播（跨端真同步保持，未被 relay 通道破坏）。

### 六、传输并存（relay 与 SSH）

- [ ] relay 连接与既有 SSH 连接在 `MachineConfig` 中并存；在两种 transport 间切换，各自独立工作、互不干扰（切到 relay 不破坏 SSH 配置，反之亦然）。

### 七、双向认证 + 一次性口令

- [ ] 用**错误 / 无效**的 pairingCode（一次性口令）发起握手，被开发机侧明确拒绝（防冒充：开发机验 iPad 签名 + 校验 pairingCodeProof）。
- [ ] 同一 pairingCode **用过一次后失效**：首次握手成功后，再用同一口令二次握手被拒（`pairingAlreadyUsed`）。
- [ ] iPad 侧验证开发机身份（校验开发机签名 / 公钥），身份不符时拒绝连接。

### 八、错误可见（不静默挂死）

- [ ] 配对信息错误 / 格式非法 / 已过期（`exp` 超时）→ iPad 明确报错，不静默挂死。
- [ ] relay 不可达（ECS 宕 / 端口不通）→ iPad 明确报错，且可重试。

### 九、配对导入 UI 基线（项目级 UI 恒定原则）

- [ ] 配对导入界面在**横屏 / 竖屏**下布局均正常（两个朝向都测，不只测单一朝向）。
- [ ] 软键盘弹出 / 收起时界面无遮挡、无跳变；粘贴 / 输入交互正常。
- [ ] 外接键盘下可正常粘贴 / 编辑 / 提交配对载荷。

### 十、已知限制（记录，非阻塞）

- [ ] （可选）弱网 / 中途断线：当前无自动重传 / 断点续传，断线需手动重连。记录此已知限制，留后续 change 处理。
